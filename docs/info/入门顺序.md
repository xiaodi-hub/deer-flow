别试图一次读完。这个项目正确的入门顺序是：先跑起来，沿一条请求链路追代码，再按子系统拆解。

**第 0 天：建立环境**

- [ ] 阅读根目录 [AGENTS.md](/G:/2026github/deer-flow/AGENTS.md)。
- [ ] 执行 `make setup`，按向导配置模型和沙箱。
- [ ] 执行 `make doctor`，解决环境问题。
- [ ] 执行 `make dev`，浏览器打开 `http://localhost:2026`。
- [ ] 新建一个会话，发送“创建一个 Python 文件并解释内容”，观察流式回答、Todo、工具调用、文件产物。

目标：先知道它作为用户是什么体验。

**第 1 天：建立全局地图**

- [ ] 阅读 [README.md](/G:/2026github/deer-flow/README.md) 的 Core Features、Sandbox、MCP、Sub-Agents、Memory 章节。
- [ ] 阅读 [backend/AGENTS.md](/G:/2026github/deer-flow/backend/AGENTS.md) 和 [frontend/AGENTS.md](/G:/2026github/deer-flow/frontend/AGENTS.md)。
- [ ] 画出这张图并写在自己的笔记中：

```text
Next.js Frontend

  -> FastAPI Gateway :8001
  -> RunManager / run_agent
  -> LangGraph Lead Agent
  -> Middleware / Tools / Subagents / Sandbox / MCP
  -> SSE events back to Frontend
```

目标：能说明每层“负责什么”，不用记住实现细节。

练习：回答“用户按下发送后，消息如何变成 SSE 返回到页面”。

**第 4 天：理解 Agent 的能力如何拼装**

- [ ] 阅读 [Agent 工厂](/G:/2026github/deer-flow/backend/packages/harness/deerflow/agents/factory.py)。
- [ ] 列出 middleware 的职责：上传、沙箱、压缩、记忆、Todo、视觉、子代理、Token 预算、澄清等。
- [ ] 用 `rg -n "class .*Middleware" backend/packages/harness/deerflow/agents/middlewares` 找到各实现。
- [ ] 重点精读 3 个：`SandboxMiddleware`、`SummarizationMiddleware`、`SubagentLimitMiddleware`。

目标：理解 Agent 不是单个 Prompt，而是一条受控的执行管线。

**第 5 天：选择一个子系统深入**

按兴趣选一个，不要同时学：

- Agent/后端：`runtime/runs`，学习执行、取消、事件、checkpoint。
- 安全/基础设施：`sandbox`，学习线程隔离、文件路径和不同沙箱 Provider。
- 先读一遍 [沙箱系统总览](./sandbox-systems.md)，再进具体实现文件。
- 可扩展性：`mcp` 和 `skills`，学习外部工具与技能包管理。
- 前端：`core/tasks` 和 `core/threads`，学习 SSE、缓存、历史分页与竞态处理。
- 产品能力：`memory` 或 `scheduler`，学习长期记忆或定时任务。

每个子系统至少完成三件事：读入口、读一个测试、画一次数据流。

**第 6 天：从测试反推设计**

- [ ] 后端先运行一个小测试，例如：
  ```powershell
  cd backend
  uv run pytest tests/test_run_manager.py -v
  ```
- [ ] 前端运行：
  ```powershell
  cd frontend
  pnpm test
  ```
- [ ] 读对应测试，回答“它防止了什么故障”。
- [ ] 特别关注 [blocking_io](/G:/2026github/deer-flow/backend/tests/blocking_io)，理解为什么异步服务要防止文件/网络操作阻塞事件循环。

**第 7 天：做一个最小改动**

选择低风险任务并完成闭环：

- 修改一个前端文案或空状态，并补一个单测。
- 给某个配置增加校验和测试。
- 给一个 API 错误场景补测试。
- 改善日志信息或开发文档。

完成标准：

```powershell
cd frontend
pnpm check

cd ..\backend
make test
```

最后写一页自己的项目笔记，包含：架构图、一次消息链路、一个子系统、一次实际改动。做到这四项，就已经不是“小白式浏览”，而是在真正建立可贡献的理解。
